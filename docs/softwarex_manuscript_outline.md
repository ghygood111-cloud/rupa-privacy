# SoftwareX manuscript outline and evidence map

This file is an outline, not a finished manuscript. Every draft claim must remain
within `docs/software_scope_and_non_goals.md` and the four contributions frozen in
`docs/softwarex_contribution_positioning.md`.

Aligned with the official Original Software Publication template, version 6
(March 2026), checked 2026-10-03: five main sections, at most 4000 words and six
figures. Keep validation within examples/impact rather than adding a sixth main
section. Source: https://legacyfileshare.elsevier.com/promis_misc/softwarex-osp-template.docx

## 1. Motivation and significance

- Describe the governance and reproducibility burden of fixed-roster industrial
  microdata release with mixed fields and public balance equations.
- Distinguish integrated workflow value from mechanism novelty.
- Position diffprivlib, OpenDP, and trasgoDP accurately.
- State the supported privacy unit and adjacency in the opening section.

## 2. Software description

- Configuration and typed data model.
- Calibration-derived single-attribute risk and utility weights.
- Field-level numerical allocation and heuristic categorical allocation.
- Standard Laplace and generalized randomized-response mechanisms.
- Public linear-equality validation, weighted projection, interpolation, clipping,
  and residual diagnostics.
- Reproducibility/production modes, privacy ledger, public/internal output split,
  and manifest.

## 3. Illustrative examples

- Built-in fully synthetic hazardous-waste/mining-style example.
- Independent water-treatment semi-synthetic example driven only by data and
  configuration.
- Third-party reuse package; report results only after a real participant completes
  the protocol.

### 3.1. Reproducible execution and validation

- P0 privacy-safety and fixed-seed regression tests.
- Formal diffprivlib comparator, trasgoDP LDP near-neighbor, and RUPA ablations.
- Categorical cardinality, long-tail, rare-category, and failure-path stress tests.
- Runtime and peak-memory scaling.
- Constraint normal, redundant, ill-conditioned, conflicting, and bound-infeasible
  cases, including core fail-closed behavior.
- Joint-NMI diagnostic audit and internal empirical attack audit.

Use version-bound evidence. P1 results from an older preprocessing implementation
are historical results, not automatically current release benchmarks. New
illustrative run plots can be generated by `reproducibility/softwarex_review.py`;
they do not establish multi-seed superiority, scalability or industrial deployment.

## 4. Impact

- Reduced integration work for researchers whose data fits the declared contract.
- Auditable public-metadata provenance and release boundary.
- Reusable experiment and governance artifacts.
- Do not convert small baseline differences into a performance-superiority claim.
- Describe the research workflow enabled, not hypothetical users as actual users.
- A reuse fixture run by the development agent is not independent reuse.

## 5. Conclusions

Summarize the four existing software contributions, verified examples and narrow
scope. Integrate the following limitations without asserting new features.

- Fixed public roster and one row per unit only.
- Heuristic categorical allocation and high-cardinality distortion.
- Joint-NMI is optional and has no material downstream advantage in current tests.
- Public linear equalities only; no nonlinear or inequality support.
- Interpolation and clipping do not guarantee exact physical feasibility.
- The primary example is synthetic and the water-treatment example semi-synthetic.
- No independent cryptographic or privacy implementation audit.
- Private calibration subjects are outside the automatic release-subject guarantee.
