# Reproducing the RUPA paper

The Chinese technical manuscript dated 2026-10-22 describes the 39-file core
identified in `reproducibility/expected/paper_core_sha256.json`. Version 0.1.0 is
retained only while those core bytes match. Licensing, documentation, CI and the
license-state test were updated for publication without changing scientific code.

## Environment and core examples

Use 64-bit CPython 3.9.13 for the exact reference checks:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r reproducibility/requirements-validation-py39.txt
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\python.exe -m pytest --junitxml=artifacts/pytest.xml
.\.venv\Scripts\python.exe reproducibility/run_all.py
.\.venv\Scripts\python.exe scripts/compare_legacy_package.py --output artifacts/legacy_comparison.csv
.\.venv\Scripts\python.exe reproducibility/verify_paper_snapshot.py
```

The one-command check actually validates, runs and inspects the official,
water-treatment and third-party-reuse examples and verifies the six legacy
references. It uses fresh temporary directories, not old output files. The reuse
fixture is synthetic configuration reuse, not independent-person replication.

To inspect the manuscript's hazardous-waste mixed-field example:

```powershell
rupa-privacy validate --calibration examples/hazardous_waste/calibration.csv --release examples/hazardous_waste/release.csv --config examples/hazardous_waste/config_reproducibility.yaml
rupa-privacy run --calibration examples/hazardous_waste/calibration.csv --release examples/hazardous_waste/release.csv --config examples/hazardous_waste/config_reproducibility.yaml --output runs --run-id paper_hazardous
rupa-privacy inspect-run runs/paper_hazardous --sensitive-target confidential_cost_index
```

## Main four-path experiment

After the full pytest gate above, run from the repository root:

```powershell
python -m experiments.two_view_review_20261022.run --output artifacts/four_path_NEW --pytest-xml artifacts/pytest.xml
python -m experiments.two_view_review_20261022.analyze --results artifacts/four_path_NEW --output artifacts/four_path_analysis_NEW
```

Use unused output directories; the driver refuses overwrites. The 25 declared
inputs comprise 10 generated hazardous-waste pairs, 10 independently generated
water-treatment pairs and 5 disjoint blocks from **one** attributed UCI Concrete
source. Each uses 30 paired seeds. These are 750 bundles and 10,500 shared output
states, not independent experiments at every state.

All paths have numerical epsilon 5 and no categorical channel. A spends 5 on
totals, B spends 5 on rows, C spends 2.5 on each view, and D post-processes exactly
C's protected draws. Feasible totals are evaluated for both A and C. D's column
sums should match C's already available feasible target within numerical
tolerance. Compare numerical metrics, not timestamps, runtime or run IDs.

The frozen driver/protocol, metric functions, saved aggregate reference results,
data provenance and input blocks are distributed for reproduction. Large
correlation/per-field CSVs can be regenerated by the driver instead of being
committed as development output. This is exploratory data reuse; five blocks do
not establish five independent domains or a confidential deployment.

## Public categorical example

```powershell
rupa-privacy validate --calibration examples/ontario_registration/calibration.csv --release examples/ontario_registration/release.csv --config examples/ontario_registration/config_reproducibility.yaml
rupa-privacy run --calibration examples/ontario_registration/calibration.csv --release examples/ontario_registration/release.csv --config examples/ontario_registration/config_reproducibility.yaml --output runs --run-id paper_ontario
rupa-privacy inspect-run runs/paper_ontario --sensitive-target registered_class_count
python examples/ontario_registration/analysis.py runs/paper_ontario
```

Prepared data are sufficient for offline execution. Regenerating them from the
original Ontario source needs network access and must match provenance hashes.
The original download/name/address data and cache are not redistributed.

The 180-run published categorical protocol and its driver are in
`experiments/softwarex_application_case_20261020`. This binary-field frequency
task is distinct from numerical microdata fidelity. Its decoded coverage error
must not be confused with raw GRR frequency error or a later sample-size
protocol. No output of a multi-seed confidential run is authorized by these
research examples.

## Evidence and release identity

The release verification report records the environment, actual test count,
wheel contents/hashes, example inspections and whether the original paper core
matches. Older 277/355/403/413/418 totals identify historical suites, not a fresh
installation. A tag/commit/DOI must be taken from the actual public release after
approval, never inferred from a local folder name.
