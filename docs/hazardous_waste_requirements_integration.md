# 危废数据需求集成说明

## 入口与定位

首页点击“查看危废字段需求”，或进入 `02 Data` 的“危废业务需求（无实际数据）”标签。
页面按基础属性、产生单位、运输与流向、处置单位四组呈现31个具名需求字段。
可筛选字段、查看含义和处理建议，下载字段对照表及待补配置清单。

这是业务需求层，不是新算法、数据集、可运行配置或正式发布结果。
数据尚未提供，不能计算风险、分配epsilon或给出业务效用结论。
页面不替换正在查看的示例，不修改session中的输入、验证状态或已完成运行。

## 接入决策

1. 四个明确数量字段是年产废量、运输重量、年处置能力和实际年处置量。
   数量字段必须先统一单位、周期和主体，再由作者提供公开边界。
2. 危废类别、代码、物理形态和所属行业可以作为有限类别候选。
   公开域必须来自预先确定的字典，不能来自私有发布样本的去重结果。
3. 标准名称、类别和具体代码须保持公开字典映射关系；名称不应与代码独立随机组合。
4. 危险特性、产废种类、许可类别及组合工艺可能多值。当前单字段GRR不会自动处理集合；
   如设计多个二元标签，全部字段必须纳入预算组合。高基数和多标签任务效用尚未验证。
5. 企业名称、信用代码、联系方式、详细地址、车牌、许可证和联单编号默认不进入公开分析表。
   内部关联键不自动成为公开名单，改编号也不能保护主体是否出现在名单中。
6. 任意自由文本和GPS轨迹没有新增隐私机制。地区、车型和运输时长等派生字段须先定义，
   不在需求页自动转换原始数据。

## 一主体一行与校准目标

优先分别定义固定年度的产生单位表和处置单位表，不能把不同主体硬拼成一行。
运输联单与轨迹属于不同粒度；若按企业保护，应先在内部明确年度汇总规则。
跨年度重复发布同一主体仍需要累计隐私预算。当前模型不保护固定公开名单的成员资格。

校准目标须经业务确认，当前API要求非退化数值目标且不公开该字段。
若年产废量被选为敏感校准目标，它不能同时作为扰动后发布字段。
校准数据与发布数据主体不重叠，并不自动给校准主体提供差分隐私保护。
GUI仍只允许公开或合成复现演示，秘密发布仍使用既有正式CLI与账本。

## 约束与使用范围

需求表没有完整的期初库存、期末库存、转入量和厂内利用量等收支字段，不能假设
年产废量等于运输量或处置量。不自动添加线性等式，也不新增不等式或非线性支持。
仅在同主体、同单位、同周期且有公开依据时，由作者显式配置线性等式。

软件支持研究性统计共享，不代替真实联单、实时运输调度或应急作业记录。
已有18字段危废合成示例和Ontario公开类别案例保持原样，不能据此宣称验证了本清单全部字段。

## 代码边界

本轮仅增加GUI、结构化需求资源、说明和测试，并更新后续发行的资源包含清单。
不修改 `src/rupa_privacy`、科学公式、验证规则、生产账本或随机性。
没有创建实际企业数据、运行结果、默认公开边界或可绕过正式验证的配置。
已发出的EXE和ZIP不会自动包含本轮修改，需另行构建新版本。
