# RUPA publication checklist

This checklist concerns the 0.1.0 source candidate prepared on 2026-10-23.
It is not a claim that GitHub publication or independent replication has occurred.

## Authorized source identity

- [x] Owner states rights and authority to publish the source.
- [x] Public software attribution supplied: 高涵（中国矿业大学）.
- [x] BSD-3-Clause LICENSE and third-party notices prepared.
- [x] Software-author and license placeholders replaced in metadata.
- [x] Candidate core checked against the paper's 39-file hash inventory.
- [x] Owner approved the exact 237-file public manifest before upload.

## Local release verification

- [x] Candidate and all reachable original history scanned for secrets.
- [x] Example provenance, third-party licenses and excluded files reviewed.
- [x] Fresh source installation and complete pytest recorded.
- [x] Wheel and source archive built, contents inspected and hashes recorded.
- [x] Fresh wheel installation, complete tests and example inspection recorded.
- [x] Legacy arrays/digests and paper outputs compared with preserved references.
- [x] Full commands, environment and failures included in the verification report.

The actual report, not a historical checked box, determines these outcomes.

## Public release after approval

- [x] Normal GitHub authentication without sharing passwords/tokens in chat.
- [x] Public repository created: https://github.com/ghygood111-cloud/rupa-privacy.
- [ ] Do not upload old transcripts, intermediate data, private Git metadata or old tags.
- [ ] Final commit, package version and `v0.1.0` tag checked for identity.
- [ ] Real release URL, installation instructions, notes, wheel/source archive and reproduction material published.
- [ ] Hosted CI result recorded as observed, not inferred from local tests.
- [ ] Real repository/docs/version URLs and commit added to paper Table 1.

## Optional archival and journal checks

- [ ] Obtain Zenodo archive identifier/DOI only from a successful actual deposit.
- [ ] Update CITATION.cff with that real DOI if archival succeeds.
- [ ] Recheck the current SoftwareX author guide at submission; local retained
      templates and past word-limit suggestions do not establish current rules.
- [ ] Confirm paper authors, order, affiliations, funding and correspondence separately.
- [ ] Arrange independent-person reproduction; local fixture reuse is not that evidence.

An ORCID, email or archive DOI is not invented to fill an optional field.
